## Why this page? Isn't there enough documentation anyway?

Yes, there is: But I wanted to write at least a little bit of my own for this project. As everything else was created by [Claude](https://claude.ai):

* The actual Code:
    * Backend in Go (using aws lambda)
    * Frontend in React/Typescript
    * Mobile frontends for iOS and Android using one Expo codebase
* Unit tests
* Integration tests
* End-to-end tests
* Integration with [github](https://aws.amazon.com)
* Integration with [SonarQube](https://sonarcloud.io/project/overview?id=guhilling_ai-assisted-todolist) and [CodeRabbit](https://www.coderabbit.ai)
* [OpenTofu](https://opentofu.org) configuration files for setting up [aws](https://aws.amazon.com) resources and deployment.
* [Perses](https://perses.dev)-Dashboards hosted on a [Hetzner](https://www.hetzner.com/) server.

For details please read the great [official documentation](https)

It's also worth mentioning that the first implementation of this project used [quarkus](https://quarkus.io) in the backend as I'm really fluent with [Java](https://www.java.com) in general and also quarkus.

For different reasons (mainly financially ...) I wanted a second version and I decided on purpose to chose [go](https://go.dev) as a language because _I'm not really familiar with it_.

So for the implementation, testing and documentation I relied completety on [Claude](https://claude.ai)

Of course it's still important to make sure guard rails are in (the correct) place and the project takes the right direction ... but then again: It's really stunning what AI can do today.
